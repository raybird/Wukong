# 執行計畫

2026-11-11 建立。風險與首要驗證依 [README](README.md)。本計畫為任務權威來源；GitHub issue 工作清單是建檔摘要。

## 實作步驟
1. 📝 SCN-001：辨識版本與資料卷，取得一致性副本。產出版本矩陣／副本驗證；無相依。完成判準：image digest、binary 版本與原始碼分列，副本可讀且不觸發正式資料遷移。
2. 📝 SCN-001：DB/WAL、頁面、各表、最大 session 與工具事件量盤點。依賴 1；產出聚合數值與 SQL。完成判準：用已知筆數對照組證明取數有效，未知不當零值。
3. 📝 SCN-001：EXPLAIN QUERY PLAN 與查詢耗時。依賴 2；產出可重跑命令、資料規模與冷暖測量。
4. 📝 SCN-002：候選 V2 最小契約與副本遷移／回復探測。依賴 1；涵蓋啟動、health、session、串流、取消、權限、模型、壓縮及清理；產出差異矩陣。失敗即記錄阻礙，不直接更換正式版本。
5. 📝 SCN-001／002：同資料、模型與任務的版本對照。依賴 3、4；比較舊部署、新版 Wukong＋V1、可運作的 V2 路徑。產出分階段耗時、RSS、throttling、寫入等待、DB 增量與全部失敗樣本。V2 契約未通過則記不可比較，不編造效能結果。
6. 📝 SCN-002：根因排序與升級 go/no-go。依賴 5；交付具版本與證據的決策、正式升級前提與回復方案；需改程式時另定實作範圍。

## 測試策略
盤點不改產品行為，以可重跑查詢及隔離實驗代替紅綠測試。SCN-001 用已知資料對照避免空結果假綠燈；SCN-002 用失敗契約案例驗證探測器確實報錯。正式部署維持唯讀，需啟停或變更時依 project.md 取得授權。後續程式修改依受影響 crate 與部署腳本補回歸測試。
